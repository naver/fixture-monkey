# v1.2.x

## v1.2.4

`register(...)`로 등록한 빌더와 샘플하는 빌더의 지시자를 하나의 우선순위 규칙으로 결정하도록 바꿔, 1.2.x에서 사라졌던 1.1.x 동작 여러 개를 되살렸습니다. 대부분의 테스트는 그대로 동작하지만, 커스텀 matcher나 `registerExactType(...)`로 빌더를 등록했거나 `fixture-monkey-starter` 없이 `fixture-monkey-jakarta-validation`을 쓰는 경우 **Breaking Changes**를 확인하세요.

#### Improvements
- 객체 생성이 약 43% 빨라졌습니다. 값마다 jqwik 생성기를 새로 만들지 않고 재사용합니다. 같은 seed로 생성되는 값은 바뀌지 않습니다.
- 각 `register(...)` 빌더를 하나의 scope로, 샘플하는 빌더의 지시자를 root scope로 다룹니다. 값, 컨테이너 크기, not-null, `setNull`, customizer, postCondition, `instantiate`가 모두 하나의 규칙으로 결정됩니다.
  - 샘플하는 빌더에 선언한 것이 항상 이깁니다.
  - 등록된 빌더끼리는 노드 위치와 관계없이 priority 숫자가 작은 쪽이 이깁니다.
  - priority가 같으면 값은 바깥 빌더, 컨테이너 크기는 안쪽 빌더가 이깁니다.
  - 그다음은 나중에 선언한 것이 이깁니다.
- 컨테이너 크기는 샘플하는 빌더의 정확한 경로 → 샘플하는 빌더의 와일드카드 → 등록된 빌더 → 기본값 순으로 정합니다. 샘플하는 빌더에서 같은 컨테이너에 닿는 정확한 경로와 와일드카드는 선언 순서로 결정합니다.

#### Bug Fixes
- `set(...)`이나 `register(...)`에 넘긴 값이 `sample()`마다 같은 인스턴스로 반환되어, 한 샘플을 바꾸면 다른 샘플도 바뀌고 `Arrays.asList(...)`, `List.of(...)` 같은 고정 크기·수정 불가 입력이 샘플 객체에 그대로 남던 문제를 수정했습니다. 1.1.x처럼 샘플마다 값을 새로 만듭니다. 인스턴스를 그대로 쓰려면 `Values.just(...)`를 사용하세요.
- 1.2.x에서 무시되던 1.1.x 동작을 복구했습니다.
  - `values[*]` 같은 와일드카드 경로의 `customize`, `postCondition`
  - 등록된 빌더에서 `set("$", ...)`로 넣은 전체 값 안쪽 필드의 `customize`, `postCondition`
  - `set("*", ...)`, `set("list[0,1]", ...)`, 컨테이너 타입으로 등록한 빌더 안의 `size("$", n)` / `set("$[0]", v)`
  - 앞뒤에 `size(...)`나 `set(...)`을 선언해도 `Values.just(...)` 값 유지
  - `set` → `customize` → `set`을 선언 순서대로 적용
- 타입에 등록한 빌더가 그 타입 배열의 요소에는 적용되지 않던 문제를 수정했습니다.
- 요소 클래스가 서로 다른 컨테이너(예: `Dog`와 `Cat`을 담은 `List<Animal>`)를 `set`할 때 실패하던 문제를 수정했습니다. 첫 요소만이 아니라 모든 요소로 요소 타입을 추론합니다.
- 중첩 컨테이너(리스트의 리스트, 맵의 맵 등) 전체를 `set`한 뒤 안쪽 값을 `set`하면 제대로 적용되지 않던 문제를 수정했습니다. 안쪽 컨테이너가 `List.of`, `Map.of`, `Collections.unmodifiableList` 같은 JDK 불변 타입인 경우도 포함합니다.
- 정수 타입에 소수·지수 표기 값의 `@DecimalMin` / `@DecimalMax`(예: `@DecimalMin("10.5") long`)를 쓰면 `NumberFormatException`으로 실패하던 문제를 수정했습니다.
- Kotlin sealed 타입 프로퍼티를 구체 하위 타입으로 결정할 때 선언된 nullability를 잃던 문제를 수정했습니다.

#### Breaking Changes
동작:
- `fixture-monkey-jakarta-validation`이 더 이상 Hibernate Validator와 Jakarta EL을 포함하지 않습니다. `jakarta.validation-api`만 남고, 구현체는 `fixture-monkey-starter`가 선언합니다. starter 없이 `fixture-monkey-jakarta-validation`을 추가했다면 테스트 의존성에 Bean Validation 구현체(예: `org.hibernate.validator:hibernate-validator`와 `org.glassfish:jakarta.el`)를 추가하세요. 구현체가 없어도 생성 값은 제약 어노테이션을 따르지만, `JakartaArbitraryValidator`는 샘플 객체 검증을 조용히 건너뜁니다.
- 커스텀 matcher(`register(new MatcherOperator<>(property -> ..., ...))`로 프로퍼티 이름, 어노테이션 등을 판정)나 `registerExactType(...)`로 `List`, `Set`, `Map` 같은 인터페이스에 등록한 빌더가, 이제 샘플하는 객체의 필드와 컨테이너 요소에도 적용됩니다. 이전에는 그 타입을 직접 샘플할 때(예: `giveMeOne(Child.class)`)만 적용되고, 다른 객체 안의 `Child` 필드는 등록하지 않은 것처럼 생성됐습니다. 이런 빌더가 직접 샘플한 객체에만 적용된다고 가정했다면, 이제 매칭되는 필드에도 그 값이 들어갑니다.

API (내부 클래스를 직접 생성하거나 확장 지점을 구현한 코드만 해당):
- **object-farm-api** (`0.1.5` → `0.1.6`):
  - `JavaNode`, `JavaMapNode`, `JavaMapEntryNode` 생성자의 두 번째 인자로 선언 타입을 받습니다. 선언 타입이 따로 없으면 구체 타입을 두 번 넘기세요. `JvmNode#getDeclaredType()`이 추가됐습니다.
  - `PathExpression#appendSegment(Segment)`, `PathExpression#hasTypeSelector()`, `Segment#ofKeyValue()`를 삭제했습니다. `PathExpression#hasWildcard()`는 `[0,1]` 같은 union 세그먼트에도 `true`를 반환합니다.
  - `PathContainerSizeResolver`가 선언 순서를 받습니다: `(PathExpression, int, ContainerSizeResolver)`.
  - `PathResolverContext`: `findExactContainerSizeResolver` / `findWildcardContainerSizeResolver` / `findTypedContainerSizeResolver` → `findContainerSizeResolver` / `findAncestorAwareContainerSizeResolver`, `Builder#addTypedContainerSize*` → `Builder#ancestorAwareContainerSizeResolver(AncestorAwareResolver)`.
- `FixtureMonkey` 생성자(MAINTAINED): 이름 기반 등록이 삭제된 뒤로 항상 비어 있던 `namedMatchers` 인자를 삭제했습니다.
- `DefaultArbitraryBuilder` 생성자와 `ArbitraryResolver#resolve`(MAINTAINED): `standbyContexts` 인자를 삭제했습니다.
- `InnerSpec#getManipulatorSet(MonkeyDirectiveFactory)` → `InnerSpec#getDirectives(MonkeyDirectiveFactory)`.
- `MonkeyContext#getRegisteredArbitraryBuilders()`, `MonkeyContextBuilder#registeredObjectBuilder(...)`(INTERNAL)를 삭제했습니다.
- 어댑터 엔진 내부(EXPERIMENTAL)를 재구성했습니다.
  - `c.n.f.projection.AssembleContext` → `c.n.f.assembly.AssembleContext`, `c.n.f.projection.ValueProjection`·`LazyValueHolder` → `c.n.f.planner`, `c.n.f.resolver.AbstractTypeResolver` → `c.n.f.planner`, `c.n.f.planner.NodeContextFactory`·`TreeContextCache` → `c.n.f.tree`, `c.n.f.tracing.AssemblyTraceBuilder` → `c.n.f.resolver`.
  - `DirectiveSet` → `ScopeSet`, `RuntimeTreeFactory` → `NodeTreeFactory`, `TypedValueExtractor` 삭제.
  - `AssemblyPlanner#plan(...)`, `AssembleContext`, `AssemblyPlan`, `AnalysisResult` 시그니처가 바뀌었습니다. `AssemblyPlan#isCacheHit()`, `ResolutionTrace.Timing#isCacheHit()`, trace 출력의 `Cache Hit` 줄을 삭제했습니다.

## v1.2.3

#### Bug Fixes
- Kotlin에서 `Type annotation class 'org.checkerframework.checker.nullness.qual.UnknownKeyFor' of the inferred type is inaccessible` 오류로 컴파일이 실패하던 문제를 수정했습니다. Checker Framework의 javac가 추론한 어노테이션을 클래스 파일에 그대로 기록해 `fixture-monkey` 1.2.2에서는 147개 클래스 중 139개가 이 어노테이션을 갖고 있었지만, `checker-qual`은 어느 POM에도 선언되지 않았습니다. 이제 nullness 검사는 아무것도 패키징하지 않는 별도 태스크에서 실행되므로, 검사가 추론한 어노테이션이 jar에 들어가지 않습니다.

## v1.2.2

#### Features
- 시나리오가 의존하는 프로퍼티만 고정하는 Java, Kotlin 테스트를 작성해 주는 `write-fixture` 스킬을 담은 Claude Code 플러그인을 추가했습니다. 이 저장소의 마켓플레이스에서 설치할 수 있으며, 같은 내용을 Agent Guide 문서로도 제공합니다.

#### Bug Fixes
- 인터페이스, 추상 클래스, Kotlin sealed 타입을 거쳐 도달하는 프로퍼티에 `register(...)`로 등록한 빌더가 무시되던 문제를 수정했습니다. 추상 타입 자체에 등록한 경우, 그 구현체에 등록한 경우, 해당 프로퍼티 하위의 타입에 등록한 경우 모두 적용되며 컨테이너 요소도 포함합니다.
- null이 될 수 없는 인터페이스, 추상 클래스 프로퍼티가 `null`로 생성되던 문제를 수정했습니다. 프로퍼티에 대해 선택된 구현체가 프로퍼티에 선언된 nullable 여부를 그대로 유지합니다.

#### Improvements
- fixture-monkey-mockito의 `org.mockito:mockito-core`를 `3.9.0`에서 `4.11.0`으로 올렸습니다. `api` 의존성이므로 Mockito 버전을 직접 고정하지 않은 프로젝트는 테스트 클래스패스에서 4.11.0을 받게 되며, Mockito 4는 3.x에서 deprecated였던 API를 제거했습니다.
- 인터페이스, 추상 클래스, Kotlin sealed 타입을 구현체로 변환하는 지점을 `InterfacePlugin`과 `KotlinPlugin`이 설정하는 `CandidateConcretePropertyResolver` 한 곳으로 통일했습니다. 트리를 만드는 동안 따로 동작하던 node promotion 단계는 제거했습니다.

#### Breaking Changes
- **object-farm-api** (`0.1.4` → `0.1.5`): `JavaInterfaceNodePromoter`를 제거했습니다. `JvmTypeSystem#nodePromoters(...)`로 `JvmNodePromoter`를 등록하는 방식은 그대로입니다.
- `KotlinInterfaceNodePromoter`와 `KotlinNodePromoters`(EXPERIMENTAL, since `1.1.0`)를 제거했습니다. `KotlinPlugin`은 더 이상 이 promoter들을 설치하지 않으며, Kotlin sealed 타입은 `KotlinPlugin`이 등록하는 candidate resolver가 처리합니다.

## v1.2.1

#### Features
- **object-farm-api** (`0.1.3` → `0.1.4`): `InlinedValueResolver`와 `FieldExtractor#reflection(InlinedValueResolver)` 오버로드를 추가했습니다. JVM 언어 플러그인이 해당 언어가 소유 객체의 필드에 인라인한 value 타입을 복원할 수 있습니다.

#### Improvements
- `JvmTypeSystem`(EXPERIMENTAL)이 `assemblyPlanner(AssemblyPlanner)` 대신 플러그인이 제공하는 개별 부품 — `nodePromoters(...)`, `leafTypeResolvers(...)`, `candidateGeneratorWrapper(...)`, `inlinedValueResolver(...)` — 을 받습니다. 모든 플러그인이 적용된 후 `FixtureMonkeyBuilder`가 이 부품들로 단일 `AssemblyPlanner`를 생성합니다. 그 결과 `JvmTypeSystemPlugin`을 여러 개 등록하면 각 플러그인이 등록한 항목이 합쳐집니다. 이전에는 마지막 플러그인이 앞선 등록을 덮어썼습니다.

#### Bug Fixes
- Kotlin `value class` 프로퍼티를 가진 객체를 통째로 `set(...)`에 넘길 때 발생하던 `IllegalArgumentException`을 수정했습니다. `kotlin.time.Duration`, `UInt`처럼 언어가 소유 객체의 필드에 인라인하는 모든 타입에 동일하게 적용되며, `PropertyNameResolver`로 이름이 바뀐 프로퍼티(예: Jackson의 `@JsonProperty`)도 함께 처리됩니다.

## v1.2.0

0.4.0부터 기본 엔진이었던 레거시 object tree 엔진이 제거되고, 1.1.17에서 실험적으로 도입되었던 adapter 엔진이 이제 **유일한 기본** 객체 생성 엔진이 되었습니다. `FixtureMonkeyBuilder`가 자동으로 연결합니다.
일상적으로 사용하는 API(`ArbitraryBuilder`, `giveMe*`, `set`/`size`/`thenApply`)는 변경되지 않았습니다. 기존 엔진 내부에 연결되던 확장 지점은 제거되었으므로 Breaking Changes를 확인하세요. 커스텀 `Property` / `PropertyGenerator` / `ArbitraryIntrospector`를 직접 구현한 경우 이번 릴리스를 주의 깊게 검토하세요.

#### Features
- JVM 언어용 확장 SPI인 `JvmTypeSystemPlugin` / `JvmTypeSystem` / `LeafTypeRegistry`를 추가했습니다. 플러그인이 `FixtureMonkeyBuilder.plugin(...)`을 통해 커스텀 `AssemblyPlanner`를 설치할 수 있습니다.
- 값 생성 디버깅을 위해 resolution tracer를 직접 연결하는 `FixtureMonkeyBuilder#tracer(AssemblyTracer)`를 추가했습니다.
- `TypeReference#getJvmType()`와 `ArbitraryGeneratorContext#getResolvedJvmType()`를 추가했습니다.
- `Types#normalizeRawType(...)`, `Types#toJvmType(...)` 오버로드, `Types#toAnnotatedType(JvmType)` 유틸리티를 추가했습니다.

#### Improvements
- `@Seed`가 `FixtureMonkeyBuilder#seed(long)`보다 우선 적용되며, seed가 테스트 단위로 스코프되고 해제됩니다. 테스트나 다른 extension이 예외를 던져도 해제됩니다. 이전에는 global seed가 테스트 간에 누수되거나 builder의 기본값(`System.nanoTime()`)에 의해 덮어써질 수 있었습니다.
- 컨테이너 크기가 같은 seed로 재실행 시 재현 가능해졌습니다. 컨테이너 크기 randomness가 값 생성과 분리된 전용 counter로 추적되어, 다른 곳의 cache hit/miss 패턴이 크기에 영향을 주지 않습니다.
- 객체 생성이 선언/iteration 순서를 유지합니다(`HashMap` 대신 `LinkedHashMap`). Kotlin aliased constructor 파라미터에 값이 잘못된 파라미터로 들어가던 문제를 수정합니다. 이로 인해 같은 seed에서도 생성되는 random stream이 1.1.x와 달라질 수 있습니다.
- `FixtureMonkeyOptionsBuilder#defaultNullInjectGeneratorOperator(...)`가 이전 operator를 덮어쓰지 않고 연속으로 합성(compose)합니다.
- `.size()`의 wildcard와 exact-path 우선순위가 빌드 시점에 결정되어, 우선순위가 높은 wildcard 크기가 가려진 exact path에도 올바르게 적용됩니다.

#### Bug Fixes
- primitive 타입 슬롯에 `null`을 주입하려다 발생하던 `IllegalArgumentException`을 방지합니다.
- `null`이 주입될 path에 `postCondition`/filter 술어(predicate)가 등록된 경우 발생하던 `NullPointerException`을 방지합니다.
- anonymous-interface proxy로 해석되는 self-referential 인터페이스 프로퍼티에서 발생하던 `StackOverflowError`를 방지합니다.
- 재귀/self-referential 컨테이너 타입(예: `List<Self>`를 포함하는 타입)이 생성 불가능한 child를 만들던 문제를 수정합니다.
- Kotlin `Pair`/`Triple` 같은 커스텀 컨테이너 타입을 올바르게 인식합니다.
- 중첩 타입에 대해 per-type introspector chain(예: `PriorityConstructorArbitraryIntrospector`)이 잘못된 `PropertyGenerator`를 사용하던 문제를 수정합니다.

#### Deprecations
- `ArbitraryGeneratorContext#getResolvedType()`와 `#getResolvedAnnotatedType()`를 deprecated 처리했습니다. `#getResolvedJvmType()`를 사용하세요.
- `PropertyUtils#toProperty(AnnotatedType)`를 deprecated 처리했습니다. 새 `toProperty(JvmType)` 오버로드를 사용하세요.

#### Breaking Changes
- `Property` 인터페이스: `getType()` 제거(`getJvmType()` 사용), `getAnnotatedType()` 제거, `getValue(Object)` 제거(값 추출은 더 이상 `Property` 계약의 일부가 아닙니다). 이에 따라 내장 구현체(`FieldProperty`, `ConstructorProperty`, `RootProperty`, `MapEntryElementProperty` 등)의 생성자 시그니처가 변경되었습니다.
- `ArbitraryGeneratorContext#getResolvedType()`의 반환 타입이 `java.lang.reflect.Type`에서 `Class<?>`로 변경되었습니다.
- `ContainerPropertyGenerator.DEFAULT_ELEMENT_RAW_TYPE`를 제거했습니다. `DEFAULT_ELEMENT_JVM_TYPE`를 사용하세요.
- 레거시 생성 엔진을 제거했습니다: `c.n.f.tree.*` 패키지, `c.n.f.expression.*`(`ArbitraryExpression`, `MonkeyExpression`, `MonkeyExpressionFactory`), manipulator 패밀리(`NodeManipulator`, `ArbitraryManipulator`, `ContainerInfoManipulator` 등)와 `NodeResolver` SPI. 이제 `AssemblyPlanner`가 자동으로 사용됩니다.
