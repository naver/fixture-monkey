Fixture Monkey는 기본적으로 실행할 때마다 다른 값을 생성합니다. 무작위로 생성된 fixture가 버그를 드러냈다면 이를 결정적으로 재현하고 싶을 것입니다. 빌더에 고정 seed를 설정하면 생성이 재현 가능해집니다.

## 빌더에 seed 고정하기

<Tabs groupId="language">
<TabItem value="java" label="Java">

```java
FixtureMonkey fixtureMonkey = FixtureMonkey.builder()
    .seed(12345L)
    .build();
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
val fixtureMonkey = FixtureMonkey.builder()
    .plugin(KotlinPlugin())
    .seed(12345L)
    .build()
```

</TabItem>
</Tabs>

seed를 고정하면 동일한 빌더가 실행마다 동일한 값을 생성하며, **v1.2.0**부터는 컨테이너 크기까지 동일하게 재현됩니다.

## 고정 seed가 같게 유지하는 것

**v1.2.4**부터 샘플이 내리는 모든 결정은 모두가 함께 쓰는 하나의 난수 흐름이 아니라, 결정이 일어나는 위치에 묶인 seed scope에서 뽑힙니다. 빌더는 만들어질 때 자신의 scope를 받고, 빌더의 각 `sample()`은 그 안에 중첩된 scope를 받으며, 각 노드는 경로를 따라 샘플의 scope 안에 중첩된 scope를 받습니다. 노드의 값, 컨테이너 크기, 인터페이스나 추상 타입의 구현체는 각각 그 노드의 scope에서 정해집니다.

그래서 같은 seed라면:

- **다른 빌더가 샘플링해도 빌더의 값이 바뀌지 않습니다.** 빌더 `B`보다 먼저 빌더 `A`를 몇 번 샘플링하든 `B`의 값은 같습니다. 단, 두 빌더를 같은 순서로 만들어야 합니다.
- **한 속성을 커스터마이징해도 다른 속성은 바뀌지 않습니다.** `set("count", 7)`이나 `size("items", 2)`를 추가하면 그 속성만 바뀌고, 다른 필드, 컨테이너 크기, 선택된 구현체는 그대로입니다.
- **샘플을 만드는 중에 생성한 빌더는 그 샘플 안에 머뭅니다.** `setLazy`나 `thenApply` 안에서 만든 빌더는 그 샘플 안에 중첩된 scope를 받으므로 뒤따르는 값에 영향을 주지 않습니다.
- **빌더의 n번째 `sample()`은 실행마다 같은 값을 줍니다.** 연속한 샘플끼리는 여전히 서로 다릅니다.
- **Kotlin도 같습니다.** `KotestPlugin`이 생성하는 Kotest `Arb`의 값이나 `setArb`로 넘긴 `Arb`의 값도 노드의 scope에서 뽑힙니다.

<Tabs groupId="language">
<TabItem value="java" label="Java">

```java
FixtureMonkey fixtureMonkey = FixtureMonkey.builder()
    .seed(12345L)
    .build();

ArbitraryBuilder<Order> builderA = fixtureMonkey.giveMeBuilder(Order.class);
ArbitraryBuilder<Order> builderB = fixtureMonkey.giveMeBuilder(Order.class);

builderA.sampleList(5);                  // builderB가 생성하는 값을 바꾸지 않습니다
List<Order> orders = builderB.sampleList(3);
```

</TabItem>
<TabItem value="kotlin" label="Kotlin">

```kotlin
val fixtureMonkey = FixtureMonkey.builder()
    .plugin(KotlinPlugin())
    .seed(12345L)
    .build()

val builderA = fixtureMonkey.giveMeBuilder<Order>()
val builderB = fixtureMonkey.giveMeBuilder<Order>()

builderA.sampleList(5)                   // builderB가 생성하는 값을 바꾸지 않습니다
val orders = builderB.sampleList(3)
```

</TabItem>
</Tabs>

:::caution
scope에 묶이는 것은 Fixture Monkey가 뽑는 값뿐입니다. 사용자 코드가 직접 뽑는 값은 모두가 함께 쓰는 난수 흐름에서 나옵니다. 예를 들어 `setLazy` 안에서 jqwik `Arbitrary`의 `sample()`을 부르는 경우가 그렇습니다. 같은 seed라면 여전히 재현되지만, 앞에서 다른 코드가 샘플링하면 값이 바뀔 수 있습니다. 대신 `Arbitrary`를 `set`에 넘기면 Fixture Monkey가 노드의 scope에서 뽑습니다.

```java
// 노드의 scope에서 뽑힘
builder.set("name", Arbitraries.strings().alpha().ofLength(8));

// 공유 난수 흐름에서 뽑힘
builder.setLazy("name", () -> Arbitraries.strings().alpha().ofLength(8).sample());
```
:::

:::info
결정을 scope에서 뽑도록 바뀌었기 때문에, 같은 seed라도 **v1.2.4** 이전과는 다른 값을 생성합니다. 특정 seed가 만든 값을 고정해 둔 테스트는 기준값을 다시 잡아야 할 수 있습니다.
:::

## `@Seed`로 단일 테스트 재현하기

JUnit 5 extension을 사용할 때는 테스트에 `@Seed`를 붙여 seed를 고정할 수 있습니다. 테스트가 실패하면 extension이 실패를 유발한 seed를 로그로 남겨 나중에 재현할 수 있습니다.

```java
@Seed(12345L)
@Test
void reproducibleTest() {
    // 항상 동일한 값을 생성합니다
}
```

:::info
**v1.2.0**부터 활성화된 `@Seed`가 `FixtureMonkeyBuilder#seed(long)`보다 우선합니다. `@Seed`(또는 `FixtureMonkeySeedExtension`)가 활성인 동안에는 빌더 자체의 seed가 무시됩니다. seed는 테스트 범위로 스코프되고 이후 해제됩니다. 테스트나 다른 extension이 예외를 던져도 해제되므로 이후 테스트로 누수되지 않습니다.
:::
