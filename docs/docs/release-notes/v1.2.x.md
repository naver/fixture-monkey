# v1.2.x

## v1.2.4

Builders registered with `register(...)` and the directives of the builder you sample are now resolved by a single precedence rule, which restores several 1.1.x behaviors that 1.2.x had lost. Most tests keep working unchanged, but tests that register a builder with a custom matcher or `registerExactType(...)`, or that use `fixture-monkey-jakarta-validation` without `fixture-monkey-starter`, should check **Breaking Changes**.

#### Improvements
- Object generation is about 43% faster: jqwik generators are reused across samples instead of being rebuilt for every value. Values generated for the same seed are unchanged.
- Each `register(...)` builder is now treated as a scope, and the sampled builder's directives as the root scope. Values, container sizes, not-null, `setNull`, customizers, post conditions and `instantiate` are all decided by one rule:
  - the sampled builder always wins;
  - among registered builders, the lower priority number wins, wherever the node is;
  - at the same priority, the outer builder wins for values and the inner builder wins for container sizes;
  - then the later declaration wins.
- Container sizes are chosen in this order: exact path on the sampled builder → wildcard on the sampled builder → registered builders → default. On the sampled builder, an exact path and a wildcard that reach the same container are resolved by declaration order.

#### Bug Fixes
- Fix a value given to `set(...)` or `register(...)` being returned as the same instance on every `sample()`, so that changing one sample changed the others, and a fixed-size or unmodifiable input such as `Arrays.asList(...)` or `List.of(...)` stayed fixed-size in the sampled object. The value is now rebuilt for each sample, as in 1.1.x. Use `Values.just(...)` to keep the instance as is.
- Restore 1.1.x behaviors that 1.2.x ignored:
  - `customize`, `postCondition` on a wildcard path such as `values[*]`;
  - `customize`, `postCondition` on a field inside a whole value set with `set("$", ...)` in a registered builder;
  - `set("*", ...)` and `set("list[0,1]", ...)`, and `size("$", n)` / `set("$[0]", v)` in a builder registered for a container type;
  - a `Values.just(...)` value kept when a `size(...)` or `set(...)` is declared before or after it;
  - `set` → `customize` → `set` applying in declaration order.
- Fix a registered builder for a type not being applied to the elements of an array of that type.
- Fix setting a container whose elements are of different classes (e.g. a `List<Animal>` holding a `Dog` and a `Cat`); the element type is now inferred from every element, not only the first one.
- Fix setting a whole nested container (a list of lists, a map of maps, ...) and then setting a value inside it, including when the inner containers are JDK immutable types such as `List.of`, `Map.of` or `Collections.unmodifiableList`.
- Fix `@DecimalMin` / `@DecimalMax` with a fractional or exponent value (e.g. `@DecimalMin("10.5") long`) failing with `NumberFormatException` on integer types.
- Fix a Kotlin sealed type property losing its declared nullability when resolved to a concrete subtype.

#### Breaking Changes
Behavior:
- `fixture-monkey-jakarta-validation` no longer brings Hibernate Validator and Jakarta EL. Only `jakarta.validation-api` stays; `fixture-monkey-starter` now declares the provider. If you add `fixture-monkey-jakarta-validation` without the starter, add a Bean Validation provider (e.g. `org.hibernate.validator:hibernate-validator` with `org.glassfish:jakarta.el`) to your test dependencies. Without a provider, generated values still follow the constraint annotations, but `JakartaArbitraryValidator` silently skips validating the sampled object.
- A builder registered with a custom matcher (`register(new MatcherOperator<>(property -> ..., ...))`, matching on a property name, an annotation and so on) or with `registerExactType(...)` for an interface such as `List`, `Set` or `Map` now also applies to the fields and container elements of the objects you sample. Previously it applied only when you sampled that type itself (e.g. `giveMeOne(Child.class)`), and a `Child` field of another object was generated as if nothing was registered. If you relied on such a builder affecting only directly sampled objects, its values now also appear in matching fields.

API (only for code that constructs internal classes or implements extension points):
- **object-farm-api** (`0.1.5` → `0.1.6`):
  - `JavaNode`, `JavaMapNode`, `JavaMapEntryNode` constructors take a declared type as their second argument; pass the concrete type twice if there is none. `JvmNode#getDeclaredType()` is added.
  - Remove `PathExpression#appendSegment(Segment)`, `PathExpression#hasTypeSelector()` and `Segment#ofKeyValue()`. `PathExpression#hasWildcard()` now also returns `true` for a union segment such as `[0,1]`.
  - `PathContainerSizeResolver` takes the declaration sequence: `(PathExpression, int, ContainerSizeResolver)`.
  - `PathResolverContext`: `findExactContainerSizeResolver` / `findWildcardContainerSizeResolver` / `findTypedContainerSizeResolver` → `findContainerSizeResolver` / `findAncestorAwareContainerSizeResolver`; `Builder#addTypedContainerSize*` → `Builder#ancestorAwareContainerSizeResolver(AncestorAwareResolver)`.
- `FixtureMonkey` constructors (MAINTAINED): remove the `namedMatchers` argument, which was always empty since named registration was removed.
- `DefaultArbitraryBuilder` constructor and `ArbitraryResolver#resolve` (MAINTAINED): remove the `standbyContexts` argument.
- `InnerSpec#getManipulatorSet(MonkeyDirectiveFactory)` → `InnerSpec#getDirectives(MonkeyDirectiveFactory)`.
- Remove `MonkeyContext#getRegisteredArbitraryBuilders()` and `MonkeyContextBuilder#registeredObjectBuilder(...)` (INTERNAL).
- Adapter engine internals (EXPERIMENTAL) are reorganized:
  - `c.n.f.projection.AssembleContext` → `c.n.f.assembly.AssembleContext`; `c.n.f.projection.ValueProjection` and `LazyValueHolder` → `c.n.f.planner`; `c.n.f.resolver.AbstractTypeResolver` → `c.n.f.planner`; `c.n.f.planner.NodeContextFactory` and `TreeContextCache` → `c.n.f.tree`; `c.n.f.tracing.AssemblyTraceBuilder` → `c.n.f.resolver`.
  - `DirectiveSet` → `ScopeSet`, `RuntimeTreeFactory` → `NodeTreeFactory`; `TypedValueExtractor` is removed.
  - `AssemblyPlanner#plan(...)`, `AssembleContext`, `AssemblyPlan`, `AnalysisResult` signatures changed. `AssemblyPlan#isCacheHit()`, `ResolutionTrace.Timing#isCacheHit()` and the `Cache Hit` line of the trace output are removed.

## v1.2.3

#### Bug Fixes
- Fix a Kotlin consumer failing to compile with `Type annotation class 'org.checkerframework.checker.nullness.qual.UnknownKeyFor' of the inferred type is inaccessible`. The Checker Framework's javac wrote the annotations it inferred into the published class files — 139 of the 147 classes in `fixture-monkey` 1.2.2 carried them — while `checker-qual` never reached a POM. The nullness check now runs in a task of its own that nothing packages, so no jar carries the annotations it infers.

## v1.2.2

#### Features
- Add a Claude Code plugin with a `write-fixture` skill that writes Java and Kotlin tests, pinning only the properties a scenario depends on. It is published from the marketplace in this repository, and the same guidance is documented under Agent Guide.

#### Bug Fixes
- Fix a builder registered with `register(...)` being ignored for a property reached through an interface, an abstract class, or a Kotlin sealed type. This covers a builder registered for the abstract type itself, for one of its implementations, and for a type nested anywhere beneath such a property, including elements of a container of them.
- Fix a non-null interface or abstract class property being generated as `null`. The concrete implementation resolved for the property now keeps the nullability declared on the property.

#### Improvements
- Bump `org.mockito:mockito-core` from `3.9.0` to `4.11.0` in fixture-monkey-mockito. It is an `api` dependency, so a project that does not pin Mockito itself resolves 4.11.0 on its test classpath; Mockito 4 removed the API deprecated in 3.x.
- Resolve an interface, an abstract class, and a Kotlin sealed type to a concrete implementation in one place, the `CandidateConcretePropertyResolver` chain that `InterfacePlugin` and `KotlinPlugin` configure, instead of a separate node promotion step while the tree is built.

#### Breaking Changes
- **object-farm-api** (`0.1.4` → `0.1.5`): remove `JavaInterfaceNodePromoter`. Registering a `JvmNodePromoter` through `JvmTypeSystem#nodePromoters(...)` is unchanged.
- Remove `KotlinInterfaceNodePromoter` and `KotlinNodePromoters` (EXPERIMENTAL, since `1.1.0`); `KotlinPlugin` no longer installs them. Kotlin sealed types are resolved by the candidate resolver `KotlinPlugin` registers.

## v1.2.1

#### Features
- **object-farm-api** (`0.1.3` → `0.1.4`): add `InlinedValueResolver` and a `FieldExtractor#reflection(InlinedValueResolver)` overload, so a JVM language plugin can rebuild value types the language inlines into their owner's field.

#### Improvements
- `JvmTypeSystem` (EXPERIMENTAL) now takes the individual parts a plugin contributes — `nodePromoters(...)`, `leafTypeResolvers(...)`, `candidateGeneratorWrapper(...)`, `inlinedValueResolver(...)` — in place of `assemblyPlanner(AssemblyPlanner)`, and `FixtureMonkeyBuilder` builds the single `AssemblyPlanner` from them once every plugin has been applied. As a result, registering several `JvmTypeSystemPlugin`s now combines what each one contributes instead of the last plugin replacing the earlier registrations.

#### Bug Fixes
- Fix `IllegalArgumentException` when an object with a Kotlin `value class` property is passed whole to `set(...)`. The same applies to any type the language inlines into its owner's field, including `kotlin.time.Duration` and `UInt`, and it also covers properties renamed by a `PropertyNameResolver` (e.g. Jackson's `@JsonProperty`).

## v1.2.0

The legacy object tree engine (the default since 0.4.0) has been removed, and the adapter engine introduced as experimental in 1.1.17 is now the **only and default** object generation engine — wired automatically by `FixtureMonkeyBuilder`.
Everyday APIs (`ArbitraryBuilder`, `giveMe*`, `set`/`size`/`thenApply`) are unchanged. Extension points that plugged into the old engine internals have been removed — see Breaking Changes. Authors of custom `Property` / `PropertyGenerator` / `ArbitraryIntrospector` implementations should review this release carefully.

#### Features
- Add a new extension SPI for JVM languages — `JvmTypeSystemPlugin` / `JvmTypeSystem` / `LeafTypeRegistry` — allowing a plugin to install a custom `AssemblyPlanner` via `FixtureMonkeyBuilder.plugin(...)`.
- Add `FixtureMonkeyBuilder#tracer(AssemblyTracer)` to attach a resolution tracer directly for debugging value generation.
- Add `TypeReference#getJvmType()` and `ArbitraryGeneratorContext#getResolvedJvmType()`.
- Add `Types#normalizeRawType(...)`, a `Types#toJvmType(...)` overload, and `Types#toAnnotatedType(JvmType)` utilities.

#### Improvements
- `@Seed` now takes precedence over `FixtureMonkeyBuilder#seed(long)`, and the seed is scoped and released per test — even when the test or another extension throws. Previously the global seed could leak across tests or be overwritten by a builder's default `System.nanoTime()` seed.
- Container sizes are now reproducible across reruns with the same seed: container-size randomness is tracked by a dedicated counter, decoupled from value generation so cache hit/miss patterns no longer perturb sizes.
- Object generation now preserves declaration/iteration order (`LinkedHashMap` instead of `HashMap`), fixing cases where Kotlin aliased constructor parameters received values on the wrong parameter. Note: for a fixed seed, the generated random stream may differ from 1.1.x as a result.
- `FixtureMonkeyOptionsBuilder#defaultNullInjectGeneratorOperator(...)` now composes successive operators instead of overwriting the previous one.
- `.size()` wildcard-vs-exact-path precedence is now resolved at build time, so a higher-priority wildcard size correctly applies at a shadowed exact path.

#### Bug Fixes
- Prevent `IllegalArgumentException` from injecting `null` into primitive-typed slots.
- Prevent `NullPointerException` when a `postCondition`/filter predicate is registered at a path that would otherwise receive an injected `null`.
- Prevent `StackOverflowError` on self-referential interface properties resolved through the anonymous-interface proxy.
- Fix recursive/self-referential container types (e.g. a type containing `List<Self>`) producing unbuildable children.
- Recognize custom container types such as Kotlin `Pair`/`Triple` correctly.
- Fix per-type introspector chains (e.g. `PriorityConstructorArbitraryIntrospector`) using the wrong `PropertyGenerator` for nested types.

#### Deprecations
- Deprecate `ArbitraryGeneratorContext#getResolvedType()` and `#getResolvedAnnotatedType()` — use `#getResolvedJvmType()`.
- Deprecate `PropertyUtils#toProperty(AnnotatedType)` — use the new `toProperty(JvmType)` overload.

#### Breaking Changes
- `Property` interface: `getType()` is removed (use `getJvmType()`), `getAnnotatedType()` is removed, and `getValue(Object)` is removed (value extraction is no longer part of the `Property` contract). Built-in implementations (`FieldProperty`, `ConstructorProperty`, `RootProperty`, `MapEntryElementProperty`, etc.) have new constructor signatures accordingly.
- `ArbitraryGeneratorContext#getResolvedType()` now returns `Class<?>` instead of `java.lang.reflect.Type`.
- `ContainerPropertyGenerator.DEFAULT_ELEMENT_RAW_TYPE` is removed — use `DEFAULT_ELEMENT_JVM_TYPE`.
- Remove the legacy generation engine: the `c.n.f.tree.*` package, `c.n.f.expression.*` (`ArbitraryExpression`, `MonkeyExpression`, `MonkeyExpressionFactory`), and the manipulator family (`NodeManipulator`, `ArbitraryManipulator`, `ContainerInfoManipulator`, …) together with the `NodeResolver` SPI. `AssemblyPlanner` is now used automatically.
- Remove the experimental adapter-bridge SPI added in 1.1.17: `NodeTreeAdapter`, `DefaultNodeTreeAdapter`, `JavaNodeTreeAdapterPlugin`, and Kotlin's `KotlinNodeTreeAdapterPlugin` — replaced by the automatic `AssemblyPlanner` + `JvmTypeSystemPlugin`.
- Remove `FixtureMonkeyOptionsBuilder#nodeTreeAdapter(...)` / `#adapterTracer(...)` and the corresponding `FixtureMonkeyOptions` getters. Use `FixtureMonkeyBuilder#tracer(AssemblyTracer)` instead.
- **object-farm-api** (`0.1.2` → `0.1.3`): remove the `JavaType` class (use `ReflectiveJvmType`) and the deprecated `JvmType#getAnnotatedType()`.
